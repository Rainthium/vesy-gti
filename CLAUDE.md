# CLAUDE.md — Единая весовая система ОАО «ГТИ»

## Что это за проект

Система управления автомобильными весами для 13 объектов ОАО «Государственная таможенная Инфраструктура» (Кыргызстан). Заменяет коммерческое ПО UniServer AUTO. Два компонента:

- **`agent/`** — служба на весовом ПК (Windows): читает весовой индикатор через COM-порт, делает снимки с 2 IP-камер (HTTP-снапшот, а камерам без него — постоянный RTSP-поток с буфером кадра, agent/cameras/stream.py), проводит цикл взвешивания, имеет локальный веб-интерфейс оператора (живое превью камер, журнал со снимками и вкладка «Диагностика» с хвостом logs/agent.log), буферизует данные офлайн: очередь фото с повторами и ротацией, ретеншн локальных снимков через 30 дней после подтверждения центром. **Одни весы = один агент** (decisions 06.08 и 11.08.2026): на объекте с несколькими весами ставится несколько экземпляров службы — в том числе на одном ПК, каждый со своей папкой, конфигом, БД, веб-портом и токеном.
- **`center/`** — центральный сервер (ВМ Ubuntu, docker-compose): API для АИС «СВХ», WebSocket-сервер для агентов, PostgreSQL, хранилище фото, веб-панель диспетчера, автообновление агентов.

**Главный документ — `docs/architecture.md`. При любом архитектурном вопросе сначала смотри туда.** Прогресс — в `PROGRESS.md` (правила ниже). Архитектурные решения — в `docs/decisions.md`.

## Незыблемые правила проекта

1. **Совместимость с АИС «СВХ»**: API v1 воспроизводит текущий контракт байт-в-байт (запрос `{ip_address, port, username, password, autoscale}` + новые необязательные поля `operation`, `vehicle_number`/`trailer_number`, `operator` (ФИО для весовой карточки, 13.08.2026) → ответ `{code, massa, weighing_datetime, unit_meas, front_image, rear_image}` + новые `tare`, `netto`). Эталон — `docs/contracts/ais-api-v1.md` (интеграции ещё нет: запросы имитирует Игорь, АИС реализует их по нашему документу — структуру диктуем мы). Менять форматы без записи в контракт нельзя. **Контракт v2 СОГЛАСОВАН с разработчиками АИС 17.08.2026 (версия 1.0)** — эталон `docs/contracts/ais-api-v2.md`: `ais_ref` (номер документа АИС WEI…/TAR…, ключ идемпотентности), `ais_object` («Специальный идентификатор СВХ», строка 0014/0013/0002) + `scale_no`, сервисный Bearer-токен + allowlist, документ операции с тарой во вложении (applied/expired/not_applied), онлайн — только синхронный REST, RabbitMQ (свой на ВМ) — только офлайн-операции, обратная связь `POST /api/v2/weighings/{id}/ais_ref`. АИС переходит сразу на v2; v1 остаётся замороженным (имитатор, страховка). Менять v2 — только новой редакцией по согласованию с АИС; план реализации — PROGRESS, этап 2.
2. **Взвешивания неизменяемы**: записанная операция не редактируется и не удаляется, только сторнирование новой записью. Единственное исключение за историю проекта — чистка ТЕСТОВЫХ операций на бою 02.09.2026 по прямому решению Игоря (decisions 02.09: бэкап в `~/backups` → триггеры `*_immutable` отключаются ТОЛЬКО внутри одной транзакции → `restart app`, чтобы агенты получили пустой реестр тар); повторять только по его указанию и только с бэкапом. Фото после сохранения не пересжимаются никогда (sha256 связан с записью). JPEG q85, родное разрешение, хранение 5 лет.
3. **Правило режимов**: при связи с центром локальное взвешивание у оператора ЗАБЛОКИРОВАНО (только через АИС). Ручной режим — только при потере связи, записи помечаются `source=local_offline` и досылаются автоматически.
4. **Расчёт нетто**: `нетто = брутто − последняя тара этой СЦЕПКИ (пара голова+прицеп) не старше 3 месяцев` (ред. 09.08.2026: смена прицепа = нет действующей тары, нужно новое тарирование; тарирование без прицепа действует только для машины без прицепа). Реестр тарирований единый (центр) и реплицируется на агентов целиком — офлайн-режим считает нетто сам. Единственный источник тары — тарирования в системе (никаких справочников тары и ручного ввода массы); оператор в офлайне вводит ТОЛЬКО номер АТС и номер прицепа.
4а. **Время**: всё пользовательское время — бишкекское (Asia/Bishkek, UTC+6, переводов нет), в БД — UTC, в API все даты — ISO 8601 с явным поясом `+06:00`.
5. **Драйверы индикаторов — сменные модули** с интерфейсом `ScaleDriver` (см. architecture §3.2). Логика взвешивания не знает о конкретном протоколе.
6. **Надёжность порта**: USB-COM переходники (CH340) подвисают (ошибка 31). Всегда: автопереоткрытие порта, не поднимать DTR/RTS для cas22, таймаут потока 3 с → статус «нет данных».
7. Секреты (токены, пароли БД, RabbitMQ) — только в `.env`/конфигах вне git. В репозиторий не коммитить. `admin/admin` не использовать нигде, кроме совместимого приёма старых запросов АИС.

## Стек и конвенции

- Python 3.12. Агент: FastAPI + pyserial + HTMX/Jinja2, SQLite-буфер, сборка PyInstaller, служба Windows (nssm). Центр: FastAPI + SQLAlchemy + PostgreSQL 16 + nginx, docker-compose. Realtime — WebSocket. Подробно — architecture §6.
- **Код и идентификаторы — английский; комментарии, докстринги, коммиты, UI — русский.**
- UI строго по дизайн-системе ГТИ: макеты в `../design/` (14 экранов, превью в `../design/превью/`), токены: Inter, primary `#0E8A5B`, поверхности `#F6F8FA`/`#EEF1F4`, радиусы 8/12/16, статусные пилюли. Не изобретать свои стили — переносить из макетов.
- Тесты: pytest. Драйверы и конечный автомат взвешивания покрываются юнит-тестами обязательно (это ядро системы). Для отладки без железа — эмулятор `tools/cas22_emulator.py` (пишется первым, см. PROGRESS).
- Линт/формат: ruff (format + check). Типизация: mypy на shared/ и драйверах.
- Один репозиторий = этот каталог `dev/`. Ветка `main` — рабочая; крупные фичи — в ветках `feat/<имя>`, слияние после прохождения тестов. Remote: `git@github.com:Rainthium/vesy-gti.git` — коммить и пушить туда регулярно. Сообщения коммитов на русском, по сути изменений.

## Протокол весов (реализовано и проверено на реальном объекте)

«CAS 22 byte» (индикаторы CAS CI-серии, напр. CI-201A): непрерывный поток, 22-байтовый пакет, 9600 8-N-1, без CRC. Разбор: `docs/protocols/cas22.md` + рабочий прототип `../docs/справка/cas22_reader.py` (проверен на СВХ «Кызыл-Кыя» 06.08.2026 — вес и фиксация совпали с табло). Использовать его логику как основу драйвера `agent/drivers/cas22.py`.
