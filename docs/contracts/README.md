## Как собрать docx из markdown

`tools/md2docx.js` (docx-js). Библиотека `docx` в репозиторий не кладётся — ставится во временную папку:

```
mkdir -p /tmp/md2docx && (cd /tmp/md2docx && npm install docx --no-audit --no-fund)
NODE_PATH=/tmp/md2docx/node_modules node tools/md2docx.js docs/contracts/customs-events-v1.md /tmp/customs-events-v1.docx
```

Проверка: скрипт валидации из skill docx (`validate.py`) требует Python ≥ 3.10 — запускать через
`uv run --no-project --with defusedxml --with lxml python <путь>/validate.py файл.docx`; структуру (заголовки,
таблицы, жирный только в шапках) удобно смотреть python-docx (`uv run --no-project --with python-docx python …`).
LibreOffice и Word на Mac Игоря нет, в PDF здесь не отрисовать — итоговый вид смотрит Игорь в Word
(10.09.2026: заголовки, таблицы, серые блоки JSON и колонтитулы отрисовались как задумано).
`pandoc -t markdown` для проверки не годится: заголовки docx-js он не распознаёт (особенность pandoc 3.10).

## Правила

- Формат согласованного контракта меняется только новой редакцией по согласованию с контрагентом;
  односторонние расширения (новые поля/коды) — с пометкой даты в шапке, незнакомые поля контрагент игнорирует.
- Контракты для АИС и таможни независимы: у каждой записи журнала свои строки outbox на каждого адресата
  (decisions 09.09.2026).
