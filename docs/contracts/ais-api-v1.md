# Контракт API v1 — АИС «СВХ» (совместимый)

Статус: действующий формат снят с боевой интеграции; расширения (`operation`, `vehicle_number`/`trailer_number`, `operator`, `tare`/`netto`/`no_valid_tare`, даты с поясом +06:00) **подтверждены 08.08.2026 и 13.08.2026 (Игорь)** — контракт заморожен как есть (правило №1). **17.08.2026 согласован нативный контракт v2** (`docs/contracts/ais-api-v2.md`, версия 1.0): АИС переходит сразу на него; v1 остаётся для имитатора `tools/ais_client.py` и как страховка на переходный период, новые поля в v1 не добавляются.

## Команда взвешивания (АИС → центр)

`POST /api/v1/weigh` (эталонный путь нашего центра; при переключении АИС меняет адрес скрипта-маршрутизатора на него):

```json
{
  "ip_address": "192.168.158.20",
  "port": 8087,
  "username": "admin",
  "password": "admin",
  "autoscale": 1,
  "operation": "weighing",
  "vehicle_number": "01KG777AAA",
  "trailer_number": "01KG500AB",
  "operator": "Акимов Нурлан Боронбаевич"
}
```

- `ip_address` + `autoscale` — legacy-ключ маршрутизации: по справочнику центра определяет объект/весы (старый адрес UniServer этого объекта). `port` сверяется дополнительно, только если он заполнен в справочнике (пустой `legacy_port` — матч по ip+autoscale при любом порте). `autoscale` — **номер весов на объекте** (подтверждено Игорем 12.08.2026): для объектов с одними весами АИС шлёт `1`; значение в справочнике менять только синхронно со стороной АИС.
- `username/password` — проверяются по базе центра (не пробрасываются дальше).
- `operation` — НОВОЕ поле (подтверждено): `"weighing"` (брутто) | `"taring"` (тарирование). Отсутствие поля трактуется как `"weighing"`.
- `vehicle_number`/`trailer_number` — НОВЫЕ поля (подтверждены): без номера ТС центру не из чего подставить тару и посчитать нетто, а тарирование не попадёт в реестр. Отсутствие полей допустимо: операция выполняется, `tare`/`netto` в ответе будут `null` (+`no_valid_tare`). Номера нормализуются (upper, без пробелов по краям).
- `operator` — НОВОЕ поле (13.08.2026): **ФИО оператора весового контроля**, строка UTF-8 (JSON), до 200 символов, регистр сохраняется. Пишется в запись операции и печатается на весовой карточке («Оператор весового контроля»). Поле необязательное: без него запись остаётся без оператора, на карточке — пустая строка подписи.
- Любой исход возвращается **HTTP 200** с полем `code` — старые клиенты разбирают тело, а не статусы. Исключение: нечитаемый JSON или отсутствие обязательных legacy-полей → HTTP 422 (старая АИС всегда шлёт все пять полей). Неверные учётные данные и неизвестный маршрут → `code: "ERR_INTERNAL"` + `message`.
- Тайм-аут всей операции — 120 с (конфигурируемо, V1_WEIGH_TIMEOUT_S).

## Ответ (центр → АИС)

Успех:

```json
{
  "code": "OK",
  "massa": 43310.0,
  "weighing_datetime": "2026-08-07T15:59:26+06:00",
  "unit_meas": "kg",
  "front_image": "/vesy/2026/08/07/913cb979ae034d0eb4748278d9f4cfcf_photo1.jpeg",
  "rear_image": "/vesy/2026/08/07/913cb979ae034d0eb4748278d9f4cfcf_photo2.jpeg",
  "tare": 15300.0,
  "tare_datetime": "2026-06-12T10:21:00+06:00",
  "netto": 28010.0
}
```

- Базовые шесть полей — как в текущей системе, с одним СОГЛАСОВАННЫМ отличием: все даты-времена теперь **ISO 8601 с явным поясом** `+06:00` (Бишкек). Отсутствие пояса в старом контракте признано ошибкой (решение Игоря, 07.08.2026); в БД время хранится в UTC. АИС должна подтвердить парсинг даты с поясом.
- `tare`/`tare_datetime`/`netto` — НОВЫЕ, только для `operation=weighing`; тара ищется по ПАРЕ голова+прицеп (ред. 09.08.2026: смена прицепа = нет действующей тары). Если действующей тары нет (>3 месяцев либо сцепка не совпала) — `"tare": null, "netto": null, "no_valid_tare": true`. Единственный источник тары — тарирования в системе (справочников тары нет).

Ошибки: `code` из перечня `ERR_AGENT_OFFLINE | ERR_SCALE_OFFLINE | ERR_NOT_ZERO | ERR_VEHICLE_TIMEOUT | ERR_UNSTABLE | ERR_CAMERA | ERR_BUSY | ERR_INTERNAL | ERR_TARE_TOO_HEAVY` (последний добавлен 04.09.2026: тарирование тяжелее лимита тары весов не проводится — гружёная машина; формат `{code, message}` прежний) + человекочитаемое `message` на русском. Семантику см. architecture §4.1. `ERR_CAMERA` — операция НЕ проведена (решение Игоря 09.08.2026: без снимков обеих камер взвешивать и тарировать нельзя); как и прочие ошибки, отдаётся только `{code, message}`, без веса.

## Фото

URL постоянные, не протухают. Доступ: заголовок `Authorization: Bearer <сервисный токен АИС>` + IP-allowlist сервера АИС. АИС проксирует фото своим пользователям. Повторное скачивание любых старых фото — в пределах хранения 5 лет.

## События (RabbitMQ)

Определены в контракте v2 (`docs/contracts/ais-api-v2.md`, раздел 7, согласован 17.08.2026): `weighing.completed` только по офлайн-операциям, брокер — свой RabbitMQ на ВМ центра (vhost `vesy`, очередь `ais-svh.weighings`), обратная связь номером документа АИС — `POST /api/v2/weighings/{id}/ais_ref`. К v1 события не привязаны.
