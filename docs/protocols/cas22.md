# Протокол «CAS 22 byte» (весовые индикаторы CAS CI-серии)

Подтверждён на практике: СВХ «Кызыл-Кыя», индикатор **CAS CI-201A**, 06.08.2026 (прототип `docs/справка/cas22_reader.py` в корне проекта vesy.gti.kg; вес и фиксация совпали с табло). Источник параметров — выгрузка настроек UniServer `CAS 22 byte.cfg`.

## Канал связи

- RS-232, типично через USB-переходник (на Кызыл-Кые — чип **CH340**).
- Параметры: **9600 бод, 8 бит, 1 стоп-бит, без чётности, без управления потоком**.
- **DTR и RTS не поднимать** (в конфигурации UniServer отключены; некоторые драйверы переходников падают при их переключении).
- Режим: **непрерывная передача** — индикатор шлёт пакеты сам, несколько раз в секунду. Команды запроса, инициализации и обнуления НЕ используются (обнуление — кнопкой >0< на панели индикатора).

## Формат пакета (22 байта)

| Байты | Содержимое | Значения |
|---|---|---|
| 0–1 | Флаг состояния (ASCII) | `ST` — вес стабилен · `US` — нестабилен · `OL` — перегруз |
| 2 | `,` (0x2C) | байт синхронизации |
| 3–4 | Режим (ASCII) | `GS` — брутто · `NT` — нетто |
| 5 | `,` (0x2C) | байт синхронизации |
| 6–7 | Знак/статус | может содержать `-` для отрицательного веса |
| 8 | `,` (0x2C) | байт синхронизации |
| 9–16 | Масса, ASCII-строка 8 символов | число, возможны пробелы ВНУТРИ строки и знак `+`/`-` |
| 17–19 | Единица измерения | `kg` (+ пробел/символ) |
| 20–21 | CR LF (0x0D 0x0A) | конец пакета |

Контрольной суммы нет.

## Разбор (проверенные правила)

1. **Синхронизация по потоку**: искать `\r\n`, брать 22 байта до него включительно; проверять запятые на позициях 2, 5, 8. Пакет, не прошедший проверку, отбрасывать и продолжать поиск (в потоке возможен мусор при подключении/обрыве).
2. **Масса**: байты 9–16 → удалить ВСЕ пробелы и `+` (пробелы бывают внутри числа — `float()` без очистки падает, из-за этого «зависал» вес в первом прототипе), затем `float`. Знак `-` — из поля 6–7 или самой строки.
3. **Стабильность**: `flag == b"ST"`. `OL` → состояние «перегруз», вес не использовать.
4. Приведение: дискретность 10 кг, множитель 1, точность 0 знаков (значения с объекта; вынести в конфиг весов — на других объектах могут отличаться).

## Таймауты и надёжность (обязательно в драйвере)

- Пакеты идут чаще, чем раз в 100 мс; **нет данных > 3 с** → статус «нет данных с индикатора» (значения из конфигурации UniServer: ReadyRxTimeOut=100 мс, RxErrorTimeOut=3000 мс).
- Переходник CH340 периодически подвисает: ошибка Windows 31 («устройство не работает») при открытии/конфигурации порта. Лечение: закрыть и переоткрыть порт с паузой; при повторении — программный перезапуск устройства (disable/enable) или уведомление в центр. Драйвер обязан уметь бесконечно переподключаться без падения процесса.
- Порт эксклюзивен: одновременно с UniServer работать нельзя (на переходный период у UniServer есть ретрансляция на соседний порт).

## Эмулятор для разработки

`tools/cas22_emulator.py` должен генерировать: пустые весы (0, ST), заезд (рост веса, US), стабилизацию (ST), съезд, обрыв потока, мусор в потоке, отрицательный вес, перегруз (OL). Скорость — 5–10 пакетов/с.
