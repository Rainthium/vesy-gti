# ПЗТК «Беловодское» — предварительная оценка (заочно)

**Статус: 27.08.2026 — оценка по фото и свидетельству о поверке, БЕЗ выезда. Внедрение отложено: объект сначала ставит новый компьютер (текущий — Windows XP).**

**ВЕРДИКТ: индикатор менять НЕ нужно — с XK3190-D2+ интегрируемся штатно.** Вопрос Игоря «покупать ли новый индикатор вместе с компьютером» — ответ НЕТ, достаточно нового ПК. Обоснование ниже.

## Весы

- Автомобильные **SCS-80**, зав. № 00000068, изготовлены в Китае. **НПВ 80 000 кг, e = 20 кг** (первые весы на 80 т в проекте; дискрета 20 — как на Алтыне, пороги цикла 400/800 подойдут). III класс точности по ГОСТ OIML R-1-76-2011.
- Принадлежат: **Филиал ЗАО «UBS Transit»** (не ГТИ — уточнить, как это влияет на договорённости по интеграции).
- Поверка: свидетельство **№ 6673 от 19.09.2025, действует до 19.09.2026** — ⚠️ **истекает через ~3 недели от даты оценки**; к моменту внедрения понадобится свежая. Поверитель Максутов Т.Р., Бишкекский центр испытаний, сертификации и метрологии; эталоны — набор гирь M1 (2000/1000/500 кг). Сертификат калибровки № ACZ202411050058 от 01.11.2024.

## Индикатор

- **Yaohua XK3190-D2+** («Weighing Monitor») — массовое китайское семейство XK3190; статический автовесовой индикатор с клавиатурой (номера машин/грузов) и печатью форм. Шильдика с зав. № и метрологией на фото нет — снять при визите.
- Задняя панель: DB25 female свободен (вероятно, параллельный принтер), два занятых разъёма (датчик + линия к ПК/табло), предохранитель.
- **RS232 к компьютеру — штатный.** По мануалу D2+ у последовательного порта есть режимы **непрерывной передачи** (X=2 — непрерывно, X=3 — непрерывно при стабильности), данные ASCII. У семейства два известных формата кадра: реверсная строка `=` + 7 цифр (как XK3190-A9) либо 12-байтовый кадр с XOR-КС (как XK3190-A12 — почти vesar). Точный вариант подтвердим дампом.
- **Главное доказательство работоспособности цифрового выхода: штатное ПО на ПК уже получает вес с индикатора** (скрин: 21 450 кг в окне программы). Физическая линия, порт и передача — живые. Наш агент просто займёт место этого ПО.

## ПК и ПО — главное отличие от прошлых объектов

- **UniServer НЕ используется.** Взвешивают через **«ProjectBalance 2008»** (окно «System of Weighing V8.0» — штатное ПО Yaohua для XK3190) на **Windows XP**.
- Следствия:
  1. Выгрузки Config-*.json не будет — параметры порта смотреть в настройках индикатора и ProjectBalance по месту.
  2. Методика дампа через SERIALTCPIP1 → ВМ недоступна — **дамп снимем напрямую**: утилитой чтения COM-порта на новом ПК или ноутбуком с USB-RS232 переходником прямо у индикатора.
  3. На XP агент не запустится — **замена ПК обязательна** (объект и так её планирует; наш вывод это подтверждает).

## Что понадобится при внедрении (когда поставят ПК)

1. Новый ПК Windows 10/11 + **USB-RS232 переходник** (на новых ПК COM-портов нет).
2. **Свежая поверка** (текущая истекает 19.09.2026).
3. Дамп потока → подтверждение формата → **драйвер `xk3190`** (третий драйвер после cas22 и vesar; протокол семейства открыт и примитивен, vesar на Кара-Суу занял один день). Заодно — момент вынести `DISCRETE_KG` в конфиг (заметка в vesar.py: «появится второй объект с другой дискретой»; здесь e=20).
4. Обычный чек-лист объекта: код АИС, № весов в АИС, маршрут к центру 192.168.140.70 (системщик), камеры, учётка весовщика, мастер-папка агента.

## Риски (почему может не получиться — все маловероятны)

- Индикатор отдаёт вес только по запросу ПО (командный режим) → лечится переключением режима порта на непрерывный в настройках самого индикатора (штатная настройка семейства).
- Возраст железа/износ → но связка работает прямо сейчас, вес в ПО идёт.
- Сценарий «менять индикатор» реален только при его физической неисправности.
