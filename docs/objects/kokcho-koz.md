## Индикатор — Yaohua XK3190-DS3

- «Digital Weighing Indicator» — версия семейства XK3190 для **цифровых датчиков** (DS = digital sensor), встроенный принтер, клавиатура (Vehicle No., Cargo No., Save Tare, Sup Print, Report form, Accu Print…). На фото табло — `0 kg`, горят Gross/St/Zero (стабильный ноль). Шильдик с зав. № не снят — при визите.
- Порт к ПК: **RS232/RS422**, скорости **600–9600** (параметр `bt`), режимы выдачи (параметр `tF`): **0 — непрерывная передача**, **1 — ответ по запросу**. Формат кадра в доступных мануалах DS3 не расписан — у семейства XK3190 два известных варианта: реверсная строка `=` + 7 цифр (A9/D2+) либо 12 байт с XOR-КС (A12); **подтвердим дампом**.
- Драйвер `xk3190` пишем **под этот объект первым** — ПЗТК «Беловодское» (XK3190-D2+) получит его готовым.
- Настройки порта и протокол — НЕ в 1С, а в службе «Сервер ВЕСЫ АВТО»: **«Менеджер сервера весов АВТО» → «Параметры весов» → «Подробно» → вкладки «Порт связи» и «Протокол обмена»** (см. раздел про ПО). В 1С на вкладке «Сервер весов 1» — только IP/порт самого сервера.

## ПО объекта — «ВесыСофт: Весовой терминал 1.0» + служба «Сервер ВЕСЫ АВТО»

- Скрины 02–03.09: «1С:Предприятие — ВесыСофт: ВесовойТерминал», **обычные формы** (меню «Правка · Справочники · Сервис · Окна · Справка», в статусе «Обработка Рабочий стол в…») — это **Весовой терминал 1.0** (снят с продаж; 2.0 — на управляемых формах и с UniServer AUTO). Журнал за 2026 г. (03.09 к 15:00 — уже №00000033449, оживлённый объект: «Поступление (Ввоз)», «Автоматически», голова+прицеп, брутто/тара/нетто), панель «Весы 1 >СТАБ< 0 / Весы пусты», чекбоксы «Камера 1–2» включены, в статусе «Подключен локальный сервер: 1:…».
- **Архитектура (docuwiki.vesysoft.ru, 1svt:install / manager:install)**: 1С-конфигурация сама с индикатором не общается. Отдельная **служба Windows «Сервер ВЕСЫ АВТО»** (DCOM-объект + Web-сервер) — драйвер индикатора и камер; 1С подключается к ней по IP/TCP-порту («Сервис → Настройка программы → вкладка «Сервер весов 1»: IP адрес и TCP/IP порт WEB-сервера весов, частота видео, тип весов»). Этот пункт меню есть только в **интерфейсе администратора 1С** — у весовщика меню урезано (как на скрине: в «Сервис» одни платформенные пункты).
- **Где настраивается индикатор**: **«Менеджер сервера весов АВТО»** (Пуск → ВесыСофт, запуск от имени администратора; обычно есть значок в трее) → страница **«Параметры весов»** → кнопка **«Подробно»** → закладка **«Порт связи»** (COM-порт, скорость — стандарт 9600, 8/1/нет) и закладка **«Протокол обмена»** (файл конфигурации по типу индикатора — там видно, каким протоколом читают DS3). Камеры — страница подключения видеокамер: «Источник» (RTSP/RTMP или HTTP JPEG/MJPEG), URL, логин, пароль, fps. Применение: снять галочку «Включить весы» → «Сохранить» → «Обновить» → вернуть галочку.
- Следствия для нас: (1) COM-порт держит служба сервера, а не 1С — значит, в com0com-схеме на виртуальный порт перенастраивается **Менеджер сервера**, 1С ничего не заметит; (2) файл протокола обмена в Менеджере — готовая подсказка по формату кадра DS3 (попросить скрин вкладки «Протокол обмена» с раскрытыми параметрами); (3) при tF=1 (по запросу) сервер сам шлёт команды — hub4com должен пропускать их в индикатор (`--bi-route`), агент только слушает.
- Подключение к индикатору — **только RS-232** (в Менеджере — COM-порт; TCP/виртуальные порты не заявлены; «переходник USB-COM не рекомендуем» → на ПК, вероятно, физический COM). ВесыСофт будет читать **виртуальный COM** из пары com0com, а раздавать поток будет hub4com.

## План ретрансляции порта (без UniServer)

**Вариант A — рекомендуемый: com0com + hub4com** (тот же проект, что наш `Setup_com0com_v3.0.0.0_W7_x64_signed.exe`; hub4com — обычный exe без драйверов, `hub4com-2.1.0.0-386.zip` с sourceforge com0com, запускается службой через nssm):

1. com0com: две пары — `CNCA0↔CNCB0` и `CNCA1↔CNCB1` (в setup включить «use Ports class» — Windows даст номера COMx, как на К-К/Д-А).
2. hub4com читает физический порт индикатора и раздаёт (черновик, синтаксис сверить с ReadMe на месте):
   ```
   hub4com --octs=off --baud=<скорость> \\.\COM<физ> --bi-route=0:1 --route=0:2 \\.\CNCB0 \\.\CNCB1
   ```
   порт 0 — индикатор; порт 1 (`CNCB0`) — ВесыСофт, двунаправленно (если он опрашивает командами при tF=1); порт 2 (`CNCB1`) — агент, только слушает.
3. «Менеджер сервера весов АВТО» → «Параметры весов» → «Порт связи»: порт `CNCA0` (его COM-номер), снять/вернуть «Включить весы»; агент → `port = "COM<CNCA1>"`.
4. hub4com службой: `nssm install ves-hub4com <путь>\hub4com.exe <аргументы>` (автозапуск, перезапуск при падении); ставить ДО службы агента.

Риски: драйвер com0com на Windows 10 обычно встаёт (К-К, Д-А); если ошибка 577 (как на Win11 Аламедина) — вариант B.

**Вариант B — аппаратный: RS232-«Y-кабель»** — TX индикатора на два RX (COM ПК для ВесыСофт + USB-RS232 для агента). Без драйверов и софта, но нужны руки и второй переходник; электрически работает на коротких линиях (один передатчик — два приёмника).

**Вариант C — агент как ретранслятор** (доработка агента): агент читает физический порт и зеркалит байты в виртуальный COM для ВесыСофт (com0com всё равно нужен) — держим в запасе, если hub4com чем-то не устроит.

## Дамп потока (для драйвера)

- UniServer-а нет → дамп снимаем прямо на ПК: **`tools/serial_dump.ps1`** (PowerShell, без установки чего-либо):
  ```
  powershell -ExecutionPolicy Bypass -File serial_dump.ps1 -Port COM3 -Baud 9600 -Seconds 120 -Out C:\dump-ds3.bin
  ```
  Пока порт занят службой «Сервер ВЕСЫ АВТО», PowerShell его не откроет (закрыть окно 1С НЕ поможет — порт держит служба). Снимать с виртуального порта ПОСЛЕ установки hub4com (ничему не мешает) или на две минуты освободить порт в «Менеджере сервера весов АВТО»: снять «Включить весы» → «Сохранить» → «Обновить», снять дамп, вернуть галочку тем же путём. Под нагрузкой — заезд машины (или человек на весах, как на Алтыне) + фото табло в тот же момент. Файл — на ВМ (scp) или в переписку.
