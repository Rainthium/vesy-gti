# Обследование: СВХ «Кызыл-Кыя» (пилотный объект)

## Весовой индикатор

- **CAS CI-201A** (шильдик подтверждён), протокол «CAS 22 byte» — см. `docs/protocols/cas22.md`.
- COM5, 9600 8-N-1, USB-переходник CH340, DTR/RTS не поднимать.
- Дискретность 10 кг. Чтение подтверждено прототипом 06.08.2026 (фиксация 1460 кг).

## Камеры (из выгрузки настроек UniServer, 07.08.2026)

Две IP-камеры (по виду URL — Hikvision-совместимые), у каждой основной поток `/Streaming/Channels/101`:

| Камера | Адрес | Поток | Родное разрешение |
|---|---|---|---|
| Камера 1 (front) | `192.168.158.120:554` | `rtsp://<user>:<pass>@192.168.158.120:554/Streaming/Channels/101` | 2560×1440 @ ~19 к/с |
| Камера 2 (rear) | `192.168.158.121:554` | `rtsp://<user>:<pass>@192.168.158.121:554/Streaming/Channels/101` | 2560×1440 @ ~19 к/с |

- **Учётные данные камер — в конфиге агента вне git** (правило проекта №7), в документации не публикуются.
- UniServer отображал поток в 640×360 и писал видеорегистратор туда же; наша система видео не пишет — только кадр в момент фиксации веса, **в родном разрешении** (architecture, «Хранение фото»).
- Обе камеры смотрят на платформу с противоположных сторон (заезд/выезд). В осях наших ролей: какая front, какая rear — уточнить при установке агента.
- Надписи (дата/время/вес) UniServer накладывал программно; на потоке камеры есть собственный OSD-таймстамп (на камерах сбита дата — «1970», на снимках это будет видно; поправить время на камерах при пилоте).
